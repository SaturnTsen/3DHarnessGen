# 27B Single-view 的 token 预算

本次在双卡 RTX A6000 上对真实样本做长度测试，保留原图片、完整历史和完整目标脚本。
使用 BF16 LoRA、chunked NLL、FSDP2、普通梯度检查点、每卡批次 1、梯度累积 1，
启用 `PYTORCH_ALLOC_CONF=expandable_segments:True`，不量化，不卸载激活，不执行验证。
测试按对象划分后只从训练集合选择样本，各长度测试独占 GPU，分别从同一基础模型开始。

## 报错的含义

这次不是 FSDP 分片设置或通信接口报错，而是模型计算时发生 `torch.OutOfMemoryError`。
FSDP 分片参数、梯度和优化器状态；每个进程仍处理自己那条样本的完整序列。
26,749 token 不会自动变成每卡约 13k token。

此前 26,749-token 样本在线性注意力的前向计算中申请 628 MiB 失败。
启用 CPU 激活卸载后前向完成，但在反向重算前馈网络时申请 890 MiB 失败。
本次约 16k 的样本前向通过，反向重算中仍显存不足。
报错中的最后一次申请大小，不等于完成整个训练步骤还缺的总显存。

## 数量估算

模型权重索引记录总大小 55,562,855,904 字节，约 51.75 GiB；
理想双卡分片后每卡约 25.87 GiB。这不包括适配器、通信缓冲和临时恢复的完整参数。

模型配置为 64 层、隐藏维度 5,120。按每层保存一份 BF16 隐藏状态估算：

```text
隐藏状态占用 ≈ 64 × 总 token 数 × 5120 × 2 / 2^30 GiB
             = 总 token 数 × 0.0006103515625 GiB
```

| 总 token 数 | 上述隐藏状态估算 | 加上理想参数分片后的合计 |
| --- | --- | --- |
| 8,192 | 5.00 GiB | 30.87 GiB |
| 10,240 | 6.25 GiB | 32.12 GiB |
| 12,288 | 7.50 GiB | 33.37 GiB |
| 16,384 | 10.00 GiB | 35.87 GiB |
| 26,749 | 16.33 GiB | 42.20 GiB |

这只是量级估算，不能把合计当作训练峰值。当前环境的线性注意力参考实现还会转为 FP32
并生成额外中间张量；反向传播、前馈网络、损失计算和 FSDP 通信也占用显存。
不能用显卡容量除以 token 数，也不能仅按报错申请大小推导安全上限。

## 实测

| 筛选预算 | 实际样本输入长度 | 更新步数 | 结果 |
| --- | --- | --- | --- |
| 16,384 | 16,068 / 16,054 | 0 | 前向通过，反向 OOM |
| 12,288 | 12,097 / 12,056 | 1 | 完成更新、检查点与最终适配器保存 |
| 10,240 | 10,240 / 10,232 / 10,226 / 10,166 | 2 | 完成连续两次更新、检查点与最终适配器保存 |

12k 测试的 PyTorch 峰值分配为 43.12 / 43.06 GiB，峰值保留为 44.96 / 45.71 GiB。
这两个口径不包含桌面等其他进程与全部 CUDA/NCCL 开销。
训练损失 0.14209，梯度范数 0.06093；训练循环约 120 秒。
中间出现过分配失败后回收重试的警告，但运行最终成功，不应把警告误判为进程失败。
检查点记录 `global_step=1`，1312 个参数已分片；适配器参数更新非零且有限。
此项只证明这些完整样本完成一次真实 27B 更新，不能代表全部数据或长期训练稳定。

输出目录为 `outputs/post_training/Single-view/fsdp_length_12k_v1`。
每个进程的结果保存在 `result_rank0.json` / `result_rank1.json`，
`probe_samples.json` 记录实际输入和目标长度，`resolved_config.yaml` 保存配置。
16k 失败记录位于 `outputs/post_training/Single-view/fsdp_length_16k_v1`。
探索脚本与日志位于 `temp/chunked_fsdp/run_length_probe.py` 和对应 `27b_length_*.log`。

10k 两步测试的峰值分配为 40.66 / 40.63 GiB，峰值保留均为 43.16 GiB；
训练循环约 177 秒，平均损失 0.16199。
第二步在优化器状态已建立后完成，梯度范数为 0.07477，检查点记录 `global_step=2`。
LoRA B 参数非零元素总数为 4,980,733，参数均有限。
输出目录为 `outputs/post_training/Single-view/fsdp_length_10k_v1`。

## 建议预算与边界

建议把 **10,240 总 token** 作为当前环境的保守起步预算。12k 真实样本可以完成一次更新，
但分配重试与保留显存峰值说明余量偏紧；16k 已实测失败。
这些短训不能证明任意图片组合、目标长度和完整训练周期均稳定。

用 10,240 和 12,097 两个实测点对主进程训练峰值做局部线性拟合：

```text
PyTorch 峰值分配 ≈ 27.10 + 1.36 × (总 token 数 / 1024) GiB
```

这一局部拟合预测 16,068 token 约需 48.38 GiB，已经超过单卡容量，符合失败结果。
如果粗略把 PyTorch 分配空间限制在 45 GiB，拟合交点约为 13,500 token；
但桌面、CUDA/NCCL、缓存和瞬时分配都需要余量，不能把这个交点用作安全配置。
它只是相似样本下的估算，不是已实测的最大长度，也不能外推到其他配置。

预算可以在已有短训配置上显式覆盖；这个命令仍然最多更新 3 步：

```bash
PYTORCH_ALLOC_CONF=expandable_segments:True pixi run post-train-distributed train \
  --config configs/sft_single_view_fsdp_trial.yaml \
  template.max_length=10240 \
  experiment.output_dir=../outputs/post_training/Single-view/fsdp_10k_trial_v1
```

## 长度限制对数据的影响

这里的长度是 Processor 编码后的总输入长度，包括历史、图片 token 和当前目标回复。
对当前 320 条训练样本，设置不同预算的覆盖情况如下：

| 总长度预算 | 保留完整样本 | 超长样本 | 保留比例 |
| --- | --- | --- | --- |
| 8,192 | 194 | 126 | 60.62% |
| 10,240 | 250 | 70 | 78.12% |
| 12,288 | 284 | 36 | 88.75% |
| 14,336 | 306 | 14 | 95.62% |
| 16,384 | 316 | 4 | 98.75% |

降低 `template.max_length` 会记录并拒绝超长样本，不会自动缩短完整脚本。
本次只做测试和记录，没有修改正式配置的数据预算，也没有裁剪原始数据。

最长的当前目标脚本本身为 12,696 token。10,240 预算下有 2 条目标本身已超过预算，
12,288 预算下有 1 条。因此，仅压缩历史并不能保证把全部长样本纳入预算；
这些目标不应通过直接截断来勉强训练。

FSDP2 的分片范围参考 [PyTorch 官方文档](https://docs.pytorch.org/docs/main/distributed.fsdp.fully_shard.html)。
